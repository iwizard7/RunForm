# RunForm

[![CI](https://github.com/iwizard7/RunForm/actions/workflows/ci.yml/badge.svg)](https://github.com/iwizard7/RunForm/actions/workflows/ci.yml)

RunForm is a local-first running workout analyzer built with Next.js.
It imports workout JSON files (or screenshots of workouts), stores them in a local SQLite database, and turns raw training data into readable coaching insights, comparisons, weekly summaries, and shareable reports.

## Quick Start (macOS)

One command on a clean Mac — installs everything, clones the repo to `~/RunForm`,
builds the app and opens it in the browser:

```bash
curl -fsSL https://raw.githubusercontent.com/iwizard7/RunForm/main/scripts/bootstrap-mac.sh -o /tmp/runform-bootstrap.sh && bash /tmp/runform-bootstrap.sh
```

What the bootstrap script does:

- installs Node 20 via Homebrew (`node@20`, added to `PATH` in `~/.zprofile`)
- clones the repository (or reuses `~/RunForm` / the current checkout)
- installs npm dependencies and verifies the native `better-sqlite3` module
- installs Ollama if missing, starts it, and pulls the default text model
  `qwen3:4b` (~2.6 GB); the vision model for screenshot import is optional
- installs a **RunForm.app** shortcut into Applications (double-click to launch)
- builds the production bundle and launches `scripts/start-workout-app.sh`,
  which opens `http://localhost:3000`

After the first setup, just double-click **RunForm.app** in Applications —
it starts the server if needed and opens the app in your browser. Or run:

```bash
~/RunForm/scripts/start-workout-app.sh
```

Prefer to do it by hand? See [Installation](#installation) below.

The app is designed for personal use on a local machine:

- workout history is stored locally
- AI review, planning, chat and analysis run through a local Ollama instance
- no cloud backend is required for the current version

## What The App Does

- Imports workout JSON files into a local history
- Recognizes workouts from screenshots (Strava, Garmin, watch photos) with a local vision model
- Builds a dashboard for the latest workout
- Shows calendar-based training history
- Computes training metrics such as intensity, MET load, efficiency, zone profile, weather stress, and recovery trend
- Generates AI-assisted workout review and next-workout planning through Ollama (streamed token-by-token)
- Chats with a local AI coach that knows your history, records and current week
- Compares two workouts side by side
- Exports visual summary cards and PDF reports

## Main Features

- Latest workout dashboard with core stats
- Heart-rate zone breakdown and effort profile
- Heart Rate Variability (HRV) readiness integration
- Custom personalized Heart Rate Zones and Threshold Pace configuration (used by the AI planner)
- Weekly load and recovery summary
- Health and training red flags
- AI explanation of workout quality (streamed)
- AI-generated next session plan with self-correction of the model's JSON output
- Workout comparison mode
- Share card export and coach-style PDF export
- Training Plans (generated by AI or created manually), with per-plan AI explanations
- Personal Bests tracking (1k, 5k, 10k, half marathon, indoor/outdoor)
- Health & Bio tracking (weight, body composition, soreness)
- Route Intelligence (automatic matching of repeating routes)
- GPS splits: pace and heart rate per kilometre plus an AI fatigue analysis
- GPS track map: offline SVG route coloured by per-km pace with start/finish markers
- Weekly AI digest (cached until the next week)
- Readiness verdict (GO / CAUTION / REST) before a hard session
- AI chat with persistent history stored in SQLite
- Wellness diary with browser voice dictation and AI reflection
- Screenshot → workout import via a local vision model
- Weekly AI plan: 7 dated days from tomorrow, saveable into Training Plans
- Model picker in Settings: choose the text/vision Ollama model from those installed (no env vars needed)
- Answer cache: repeated AI actions reuse the cached reply instead of re-running the model
- Russian and English UI support

## Requirements

Before running the project, make sure you have:

- **Node.js 20** — pinned via `.nvmrc` and `engines` in `package.json`. The bundled
  `better-sqlite3` binary must match the Node major version; with nvm just run `nvm use`.
  If you switch Node versions, run `npm rebuild better-sqlite3`.
- npm
- Ollama installed if you want AI features

Models for AI features (both stay local):

```bash
ollama pull qwen3:4b       # text: review, planning, chat, digests (default, fits 8 GB RAM)
ollama pull qwen2.5-vl:3b  # vision: screenshot → workout import
```

The model used per device can also be picked in **Settings → AI Model (Ollama)**
from whatever `ollama list` shows — env vars are just defaults.

Configuration via environment variables (all optional):

```text
OLLAMA_URL           # default http://localhost:11434/api/generate
OLLAMA_MODEL         # default qwen3:4b
OLLAMA_VISION_MODEL  # default qwen2.5-vl:3b
OLLAMA_KEEP_ALIVE    # default 30m — how long a loaded model stays resident
```

## Running The App

### Recommended: desktop shortcut

```bash
./scripts/install-launcher.sh
```

Installs a `RunForm.app` bundle into `/Applications` (falls back to
`~/Applications` if you don't have write access) with a custom icon.
Double-clicking it:

- opens `http://localhost:3000` right away if the server is already running;
- otherwise starts Ollama/the server via `scripts/start-workout-app.sh`
  (notification appears while it boots) and opens the browser when ready.

The project path is baked into the shortcut, so re-run the script after
moving the repository. The bootstrap script installs the shortcut automatically.

### Startup helper script

The repository includes:

```text
scripts/start-workout-app.sh
```

This script:

- verifies that the current Node runtime can load `better-sqlite3` (with a clear error otherwise)
- checks whether Ollama is responding on `localhost:11434` and starts it if needed
- checks whether the app is already running on `localhost:3000`
- rebuilds the app when sources changed
- starts the app in production mode and opens the browser

Run it with:

```bash
./scripts/start-workout-app.sh
```

## Ollama Setup

If you want the AI features to work, start Ollama locally:

```bash
ollama serve
```

Make sure the expected models exist:

```bash
ollama list
```

The loaded model is kept resident for `OLLAMA_KEEP_ALIVE` (default 30 minutes)
so repeat AI actions answer instantly instead of paying the 10–30 s cold load
again. Without Ollama, the app still opens, but every AI action (advice, plan,
chat, digest, readiness, split analysis, reflection, screenshot import) fails
with a local error message in the UI.

## Data Storage

RunForm stores imported workouts in a local SQLite database:

```text
data/workouts.db
```

The database holds workouts, personal bests, training plans, body metrics, routes, shoes and the AI chat history.

Important:

- this database is intentionally ignored by git
- your local workout history is not committed to the repository
- deleting `data/workouts.db` resets the stored history

## Input Data

The app expects workout JSON with fields such as:

- workout identity and dates
- duration, calories, distance, pace
- average, min, and max intensity
- average METs
- average, min, and max heart rate
- cadence and step count
- heart-rate zones and pace zones
- heart rate variability (HRV)
- weather and device metadata
- optional GPS track (`route` / `locations` / `routePoints`) with heart rate and timestamps

Parsing logic lives in:

- [src/lib/parser.ts](src/lib/parser.ts)

Database persistence lives in:

- [src/lib/db.ts](src/lib/db.ts)
- [src/lib/actions.ts](src/lib/actions.ts)

## Notes

- The project is local-first and currently optimized for a single-user desktop workflow
- The startup helper assumes Ollama is reachable at `localhost:11434`
- Voice dictation uses the browser's Web Speech API (Chrome/Edge and recent Safari); it degrades gracefully elsewhere
- The local database is excluded from version control by `.gitignore`

### v0.13.0 (Latest)
- **Race plans**: a periodized plan from today to a target race — pick the distance (5 km / 10 km / half / marathon), the race day and how often you run per week; the local model fills in a week-by-week schedule with phases (base → build → peak → taper), and the Plans tab renders it grouped by week. - **Post-run notes with voice dictation**: every workout in the History tab now takes a free-text note — type it or dictate it with the Web Speech API right after the run. Notes survive re-imports (they live outside the import path) and render inline on the workout card.

### v0.12.0
- **Route segments**: mark any slice of a recognized course (e.g. the finishing straight) as a segment and get local Strava-style tracking — personal bests, full attempt history with rank, time and pace, and automatic scoring of every run on the route, including future imports. Segments are defined by picking start/finish anchors ~50 m apart from the route's GPS track right in the Routes tab; database tables `segments` and `segment_efforts` with migration v9.

### v0.11.1
- **Training form window**: when the latest workout is older than 90 days, the CTL/ATL/TSB chart automatically widens its window (up to a year) so the form chart shows the real training history instead of an empty strip.

### v0.11.0
- **Training form**: the Fitness Index tab now shows CTL/ATL/TSB — the classic training-form chart (chronic fitness, acute fatigue and their balance) computed from heart rate against your lactate-threshold HR, or from workout intensity when no threshold is set.
